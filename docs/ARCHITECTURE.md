# 系统数据流与职责边界

更新：2026-10-30。返回[目录导航](../ARCHITECTURE.md)。本页说明预测、评价与诊断怎样分离，模块入口见[代码阅读路线](CODE_READING.md)。

## 从图像到地面轨迹

C1/C2/C3表示三台固定标定相机。默认B3使用三路图像：YOLO11n行人框 → 框底边中心 → 标定逆单应投影到米制地面XY → 地面区域和相机正深度检查 → 同帧融合 → 跨时刻跟踪 → 相机/地面展示与CSV。

融合按C1→C2→C3顺序处理，使用完整成员0.75米距离门，每相机在每组至多一个观测，成员唯一；未融合观测可保留为单组，组位置取等权平均。时间层使用Norfair原贪心关联，距离严格小于1.5米；FilterPy状态为[X,Y,Vx,Vy]，以0.5秒物理时间构建转移与噪声模型。生命周期计数与物理时间步分开。

`obs_id`标记单相机观测，`fusion_id`标记当前帧融合组，`track_id`标记本次运行内跨时刻轨迹。不同条件的相同号码不表示同一人。当前有观测支持的状态为observed，当前仅由运动模型外推的状态为predicted；后者不复用旧检测框。

## 评价和诊断只读预测结果

真实标注GT在预测完成后才参与评价，不进入检测、融合、跟踪。空间评价检查地面位置覆盖；身份评价使用完整GT×观测距离关系与整段全局对应，详见[评价协议](EVALUATION.md)。

E005/E006在固定三相机组上比较时间关联候选；E007读取双/三相机的组、成员、轨迹与评价导出，分析新增和损失，机械统计与人工案例判断分别保存。候选和诊断模块独立于默认预测路径。

## 运行入口与资产边界

`demo_delivery`提供三个入口：images从原图推理；replay从已保存的地面观测重新融合/跟踪；play播放已有本地视频。replay跳过检测与投影计算，但展示仍需原图和标定。`showcase`绘制全部当前状态的总览与局部放大，地面X/Y使用相同米制比例。

输入资产和参考数值只读，新结果写新的输出目录。入门使用[public_demo_reference配置](../configs/public_demo_reference.json)，原研究配置依赖各阶段的完整档案，前提见[配置导航](../configs/ARCHITECTURE.md)和[快速开始](QUICKSTART.md)。

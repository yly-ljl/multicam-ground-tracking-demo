# 系统数据流与边界

更新：2026-10-30。返回[目录导航](../ARCHITECTURE.md)。

正式预测从图像或已存预测观测开始：YOLO框→底边中心像素→固定标定逆单应→米制XY→ROI/深度检查→按C1/C2/C3顺序同帧组装→等权组位置→GroundTracker真实时间更新→相机/地面展示与CSV。默认B3不使用GT、人工身份、评价映射或E007诊断标签。

同帧融合用完整成员0.75m门，每相机每组至多一个观测，成员唯一；允许未融合单组保留。时间层使用Norfair原贪心严格<1.5m，FilterPy状态[X,Y,Vx,Vy]，0.5秒F/Q；生命周期period=1与物理dt分开。obs_id是单相机观测，fusion_id是当前帧组，track_id是条件内部的跨时刻轨迹；不同条件同数字不代表同人。

独立评价只在预测完成后读取GT：空间匹配按池/区域单独计算，身份评价用完整GT×observed距离关系和整段全局对应。E005/E006从固定组另做时间候选，默认预测不启用；E007只读原B2/B3组/成员/轨迹/评价导出，机械拆分与人工语义分开。未采用候选与诊断代码保留用于复核，不代表默认部署路径。

demo_delivery是对外入口包装：images从原图推理，replay从发布缓存重新融合/跟踪，play只播放已有本地视频。showcase保留全部当前状态总览和明确范围的zoom，X/Y同米制比例，不为展示删坏轨迹。当前无观测状态为predicted，不复用旧检测框。

输入资产只读，输出必须新目录。原研究配置可能依赖未发布档案，对外配置单列，原件不改。各模块文件说明见[tracking_demo](../tracking_demo/ARCHITECTURE.md)，推导与入口片段见[代码阅读](CODE_READING.md)。
